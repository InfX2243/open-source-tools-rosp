How to Use DataGuard

A quick visual guide on how to configure quality rules, test datasets, and integrate quality gates into your pipelines.

Step 1
Choose Your Dataset

Select or drag-and-drop any CSV, JSON, NDJSON, or Parquet file. DataGuard uses high-performance Polars multi-threading to read millions of rows in milliseconds.

Supported: .csv, .tsv, .json, .parquet, SQLite/PostgreSQL
Step 2
Write Declarative Rules

Define constraints in human-readable YAML: required non-nulls, data types, uniqueness, numeric ranges, standard formats (email/url), and whitelists.

email: { type: string, required: true, format: email }
Step 3
Inspect Score & Flaws

DataGuard calculates a transparent 0–100% Quality Score and highlights the exact row numbers and offending values for every failed rule.

Row #3: 'invalid-email' -> Failed pattern check
Step 4
Enforce CI/CD Gates

Add DataGuard to GitHub Actions with --fail-on high. If critical or high-severity rules fail, the command exits with code 1 to halt the build.

dataguard validate data.csv --fail-on high

Rule Syntax Cheatsheet

Check Type YAML Property Description Example YAML
Non-Null / Required required: true Disallows null, None, or empty string values email: { required: true }
Data Type type: <type> Conforms to integer, float, string, boolean, date, datetime customer_id: { type: integer }
Uniqueness unique: true Ensures all checked column values are distinct order_id: { unique: true }
Value Bounds min, max, between Enforces inclusive numerical or date boundaries age: { between: [18, 120] }
Standard Formats format: <name> Built-in regex formats: email, url, uuid, ipv4, phone email: { format: email }
Allowed Whitelist allowed: [val1, val2] Limits values strictly to a predefined list status: { allowed: [active, pending] }
Custom Expression custom_expr: "..." Evaluates safe Python expression on val code: { custom_expr: "val.startswith('CUST')" }
